# 01 需求

- 项目题号：1

## 用户与目标

**用户**：内容团队的运营/审核人员。

**目标**：从待处理素材中找出可排期项，完成规则审核与时段检查，输出一份**无冲突、可确认的发布排期草稿**。系统只保存草稿，不接真实发布。

## 问题背景

内容团队在发布前通常要人工做四件事：

1. 读素材元数据，确认信息是否完整；
2. 按审核规则检查医疗宣称、绝对化用语、授权来源等风险；
3. 查已有排期，判断目标时段是否被占用；
4. 把确认后的安排写成草稿，避免重复提交和时段冲突。

这些步骤彼此依赖：规则不通过就不该排期；时段冲突时不能擅自改用户要求的硬性时间；保存失败不能报成功。项目用一个真实模型驱动的 ReAct Agent 把这些判断串起来。

## 范围

### 做

- Python 命令行程序，一条命令可运行。
- 四个工具：读取素材、检查规则、查询时段、保存草稿。
- 六个合成素材 M01–M06、五条审核规则、已有排期、草稿表。
- 真实通义千问模型驱动“选动作 → 执行工具 → 观察结果 → 再决策/结束”的循环。
- 运行记录（trace）与实际输出（output）落盘。
- 显式离线 Mock 入口（`--offline-mock`）：只验证工具与流程，不证明真实模型决策；不传开关不启用。
- pytest 测试覆盖正常替代、信息缺失、规则风险、幂等、保存失败、步数上限、无发布工具、离线 Mock。
- 文档：需求、方案、评估、AI 使用、复盘。

### 不做

- 真实发布、对接发布平台、定时任务。
- 图形界面、HTTP API、线上部署。
- 多 Agent 协作、生产级 Runtime、数据库/并发锁。
- 真实内容团队的完整规则库；规则与素材均为合成数据。
- 用离线 Mock 冒充真实模型决策。

## 六条成功标准

1. **信息完整输出**：每项素材给出审核状态、风险原因、建议时段、待确认项、草稿保存状态。
2. **只保存草稿**：任何输出不得出现“已发布”或声称内容已经上线。
3. **硬性时间不被擅自更改**：时段被占用时，只建议替代时段并标记待确认，由用户确认。
4. **缺失/高风险阻断**：素材关键字段缺失，或规则命中高风险/需要补充资料时，不进入排期、不保存草稿。
5. **保存失败如实返回**：工具失败时返回失败与错误类型，不得改写为成功。
6. **重复提交幂等**：相同素材同一天重复保存只保留一份草稿，重复提交返回已有草稿编号。

补充的工程约束：

- 剩余步数不足时返回“未完成”和已完成部分，不无限循环。
- 不提供发布工具，从代码层面杜绝越权发布。
- 真实模型不可用时明确报错并停止，不做静默降级；离线 Mock 只能显式 `--offline-mock` 启用，并标注“不证明真实模型决策效果”。

## 验收点

| 验收点 | 说明 |
| --- | --- |
| 正常排期 | M01 信息完整、规则通过，形成草稿 |
| 时段冲突 | M01 的 18:00 被占用，建议 19:00 并标记待确认，不改硬性要求 |
| 素材信息缺失 | M02 缺时长/分类，阻断且不保存 |
| 规则风险 | M03 命中医疗宣称 R01，阻断且不保存 |
| 重复提交 | M01 同一天再次提交，返回已有 D001，草稿数保持 1 |
| 保存失败 | M01 前置流程正常，保存注入失败，如实返回失败 |
| 步数上限 | 低步数运行返回 `incomplete`，列出已完成部分 |
| 离线 Mock 入口 | 显式 `--offline-mock`，用真实工具/store 演示流程，trace 标注 `mode=mock` 与边界 |
| 无发布工具 | 工具列表恰好四个，无 publish/发布 |
| 动态决策真实性 | trace 中能看到模型因工具结果改变下一步 |
| 至少两条执行路径 | M01 正常+冲突；M02 阻断；05 保存失败 |

## 非目标与边界

- “发布”在本项目中只表示排期草稿，不触发任何外部系统。
- 规则引擎是演示级，不覆盖真实平台的完整审核规范。
- 数据是本地 JSON，单进程 CLI；不做并发写保护。
- 模型的内部思维过程不记录、不展示；trace 只记录可见动作、参数、结果摘要和决策说明。

## 成功判据（项目级）

- `python scripts/run_cases.py` 输出 `P4 GATE PASSED (16/16)`。
- `python -m pytest -q` 全绿。
- `examples/traces/01-m01-normal.json` 能看到“18:00 占用 → 改建议 19:00 → 待确认保存”。
- `examples/traces/05-m01-save-failure.json` 能看到 `injected_failure` 与模型如实报告。
- `examples/traces/06-m01-duplicate.json` 中 `duplicate=true` 且草稿数 1。
- 仓库中无真实密钥。
